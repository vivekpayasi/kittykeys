# Themes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** SwiftKey-style keyboard themes: a gallery of ready-made themes, and themes of your own built in an editor
with a live keyboard preview.

**Architecture:** A theme is plain data (`ThemeSpec`) in `KeyboardCore`, where every colour rule is decided and
unit-tested. `KeyboardUI` turns a spec into a `KeyboardTheme` of UIKit colours and fonts and draws it. The app writes
the chosen theme ids into `KeyboardSettings` and the custom themes into the App Group; the keyboard reads both each
time it appears.

**Tech Stack:** Swift 6.2, UIKit (Core Animation layers) in the keyboard, SwiftUI in the app, Swift Testing.

**Spec:** this file's Request and Design sections; `docs/design.md` §4.4 and §9 (Settings) are updated to match in
Task 5.

## Design

Rulings are Claude's calls unless marked.

- **T-R1, what a theme sets:** background (a colour, or iOS's own keyboard backdrop), letter-key colour,
  function-key colour, letter colour, function-key label colour, hint colour, accent, key style, key shadow,
  return key in the accent, font design and font weight. The user named borders, background colour, font and shadow;
  the rest is SwiftKey's usual set.
- **T-R2, key styles:** Filled (Apple's look), Outlined (a 1.5 pt outline in the key's colour, no fill) and
  No borders (labels on the background; a key shows its colour only while pressed). SwiftKey's "key borders" switch
  is Filled versus No borders; Outlined is extra and cheap.
- **T-R3, roles:** every key has a role. *Letter* (letters, numbers and symbols above the bottom row) and *space*
  rest in the key colour. *Punctuation* (characters on the bottom row: `,` `.` `@` `/` `.com`), *function* (shift,
  ⌫, 123/ABC, 😊, 🌐) and *return* rest in the function-key colour, as today. Function and return labels take the
  function-key label colour: that is the user's neon green on shift, ⌫ and return. Punctuation keeps the letter
  colour; space keeps the hint colour.
- **T-R4, pressed keys:** Filled keys swap to the other key colour, as today. Outlined and No borders keys fill with
  their own colour. If that fill can't be told from what is under it (contrast below 1.15), it is mixed 20% toward
  the key's label colour instead, so a press always shows. If the label can't be read on the fill (contrast below 2),
  the fill moves halfway to the background; space is left out, its label being dim on purpose. No ready-made theme
  is affected. Shift while on looks pressed, as today. (The readability rule was added in Task 4, after a custom
  theme's shift-on arrow vanished on the simulator.)
- **T-R5, return in the accent:** the return key rests in the accent in every key style, with black or white text,
  whichever reads better (white when the accent's luminance is at most 0.4). Pressed, it mixes 25% away from that
  text colour (toward black under white text), so the text only gets easier to read.
- **T-R6, derived colours:** the popups (key preview, long-press and skin-tone popups) use the key colour, or for a
  dark key (luminance below 0.18) the key colour mixed 15% toward white; when that is too close to the background
  (contrast below 1.1), it is mixed 15% further toward the letter colour. The long-press selection and the search
  caret use the accent. The emoji search field uses whichever key colour stands out more from the hint colour. These
  rules reproduce today's light and dark keyboards (dark popup `#818184` for today's `#828286`).
- **T-R7, shadow:** only Filled keys draw a shadow, and only when the theme turns it on.
- **T-R8, fonts:** the system font in four designs (Default, Rounded, Serif, Monospaced) and four weights (Light,
  Regular, Medium, Bold), so no font files ship. Key labels, the popups and the emoji panel's ABC use them; corner
  hints use the design at Regular. Key icons (😊) follow the weight. Function keys' symbol labels (⇧ ⇪ ⌫) use the
  standard design at the theme's weight, because Serif and Monospaced draw them small or thin.
- **T-R9, ready-made themes:** Automatic (today's look: iOS's backdrop, light or dark with the phone and the field),
  Light, Dark, Neon (black, neon-green function labels: the user's Android theme), Midnight, Amber (No borders),
  Synthwave (Outlined), Terminal (No borders, monospaced), Paper (serif) and Rose (rounded). Ids are stable strings;
  values are in Task 1. Every preset must pass the readability check in Task 1.
- **T-R10, a theme for dark mode:** iOS draws the strip below the keys (🌐 and the microphone) itself, light or dark
  with the phone, and a keyboard can't paint it or change it. Seen on the iOS 26.4 simulator with a spike: drawing
  outside the keyboard's view is clipped, and overriding the input view's appearance doesn't reach the strip. So a
  black theme in light mode sits on a light strip. Settings therefore has *Theme* and *In dark mode* (default: same
  as Theme). Dark mode means what Automatic already uses: the phone in dark mode, or a field asking for a dark
  keyboard.
- **T-R11, background shape:** a theme's background fills the keyboard's own rectangle, square-cornered, like other
  third-party keyboards on iOS. In home-screen search a sliver of iOS's rounded container shows above it (seen on the
  simulator); accepted.
- **T-R12, your own themes:** any number, each with a name. New themes start as a copy of the theme picked in that
  slot, named "My theme", "My theme 2" and so on. A ready-made theme can't be edited, but "Customise" copies it.
  Edits save as they happen. Deleting a theme in use puts that slot back to Automatic (or Same as Theme).
- **T-R13, storage:** `KeyboardSettings.themeID` (default `"automatic"`) and `darkThemeID` (default `""`, same as
  Theme). Custom themes are JSON under `kittykeys.customThemes` in the App Group, ids `custom-<UUID>`. Decoding is
  forgiving: a bad field takes its default, a theme without an id is dropped, the rest load. An unknown dark-mode id
  falls back to Theme's theme; an unknown Theme id falls back to Automatic.
- **T-R14, the app:** Settings gains a Theme section with two rows, *Theme* and *In dark mode*, each opening a
  gallery: a grid of cards, each a small drawing of the keyboard in that theme. Tap to pick. Your themes follow the
  ready-made ones, with a New theme card. The editor shows a working kittykeys keyboard in the theme at the top of
  the screen, with the controls below it. (Moved from the bottom after review: iOS's colour picker sheet covered it
  there.)
- **T-R15, out of scope:** photo backgrounds (SwiftKey's photo themes; they cost a few MB of the keyboard's memory
  and need a cropper), gradients, glow, key-size or key-gap settings, per-key colours, sharing themes. Photo
  backgrounds are the obvious next step if the user wants them.

## Global Constraints

- iOS 26+, iPhone only; `KeyboardCore` builds on macOS for `swift test`, so no UIKit there.
- The keyboard never traps: bad saved data falls back to defaults.
- Typing stays instant: nothing theme-related runs per keystroke beyond comparing two specs; key colours are computed
  once per key layer build.
- Keys saved before the rename keep `catkeys.`; new defaults keys use `kittykeys.` (`kittykeys.customThemes`).
- Bundle ids and the App Group never change.
- Comments and copy follow the repo's style: plain sentences, British spelling in both ("colour", "Customise"),
  as the app already says "full stop".

## Review Focus

- A custom theme deleted while picked: the keyboard must show Automatic, not crash or keep stale colours. (Task 2
  test `removingAPickedThemeResetsTheSlot`; Task 1 test `unknownIdsFallBack`.)
- Two key colours set equal, or a key colour equal to the background: presses must still show. (Task 1 tests
  `pressedFillShowsWhenColoursMatch`.)
- Saved theme JSON from a future or broken version: other themes and settings still load. (Task 2 test
  `customThemesSkipBadEntries`.)
- A long theme name or many custom themes in the gallery: cards stay laid out (manual check in Task 4).
- Switching the phone between light and dark while the keyboard shows, with a dark-mode theme set: the theme follows.
  (Task 1 test `darkSlotPicksByAppearance`; Task 3 simulator check.)

### Task 1: Theme data and colour rules (KeyboardCore)

**Files:**
- Create: `Packages/KittykeysCore/Sources/KeyboardCore/Theme/ThemeColor.swift`, `ThemeSpec.swift`, `Themes.swift`

**Interfaces (produces):**
- `public struct ThemeColor: Hashable, Sendable, Codable` — `init(rgb: UInt32)`, `init?(hex: String)` (accepts
  `#RRGGBB` or `RRGGBB`, any case), `var rgb: UInt32`, `var hex: String` (`"#RRGGBB"`, upper case),
  `red/green/blue: Double` (0...1), `var luminance: Double` (WCAG relative luminance),
  `func contrast(with: ThemeColor) -> Double` (WCAG ratio), `func mixed(with: ThemeColor, _ amount: Double) -> ThemeColor`
  (per channel, rounded), `static let black, white`. Encodes as its hex string.
- `public enum KeyShape: String, Codable, CaseIterable, Sendable { case filled, outlined, borderless }`
- `public enum FontDesign: String, Codable, CaseIterable, Sendable { case standard, rounded, serif, monospaced }`
- `public enum FontWeight: String, Codable, CaseIterable, Sendable { case light, regular, medium, bold }`
- `public enum KeyRole: Sendable { case letter, punctuation, space, function, returnKey }`
- `public struct ThemeSpec: Codable, Hashable, Sendable, Identifiable` — stored: `id, name: String`,
  `background: ThemeColor?` (nil = iOS's backdrop), `key, specialKey, label, functionLabel, hint, accent: ThemeColor`,
  `keyShape: KeyShape`, `keyShadow, returnKeyAccent: Bool`, `fontDesign: FontDesign`, `fontWeight: FontWeight`.
  Derived: `popup, searchField, onAccent, previewBackdrop: ThemeColor`; `restingFill(_:) -> ThemeColor?` (nil = no
  fill), `outline(_:) -> ThemeColor?`, `pressedFill(_:) -> ThemeColor`, `labelColor(_:) -> ThemeColor`,
  `hasShadow(_:) -> Bool`, all taking a `KeyRole`.
- `public enum Themes` — `static let automaticID = "automatic"`, `customIDPrefix = "custom-"`,
  `automaticLight, automaticDark: ThemeSpec`, `presets: [ThemeSpec]` (Automatic first, as `automaticLight`),
  `static func spec(id: String, custom: [ThemeSpec], isDark: Bool) -> ThemeSpec?`,
  `static func active(themeID: String, darkThemeID: String, custom: [ThemeSpec], isDark: Bool) -> ThemeSpec`,
  `static func newCustom(from base: ThemeSpec, existing: [ThemeSpec]) -> ThemeSpec`.
